# Демонстрационный frontend — Logistics Atlas

Ветка: `codex/backend-demo-ui`. Интерфейс работает с текущим REST API Go/Gin.

## Запуск

Из корня репозитория:

```sh
docker compose up -d --wait postgres
cd backend/main
go run .
```

В другом терминале:

```sh
cd frontend
npm ci
npm run dev
```

Открыть `http://127.0.0.1:5173`. По умолчанию Vite проксирует `/api` и `/health`
на `http://127.0.0.1:8080`. Для другого адреса:

```sh
BACKEND_URL=http://127.0.0.1:18080 npm run dev
```

Production-сборка: `npm run build`. При размещении статики нужен reverse proxy
для `/api` и `/health` на backend; Vite proxy применяется только в dev/preview.
Переменная BACKEND_URL задаётся при старте Vite/сборке; в ней не должно быть секретов.

## Что показывать

1. Начальный экран отображает **явно обозначенный локальный пример** с 12 узлами.
   Это иллюстративные объекты и связи, не выгрузка OSM и не расчёт backend.
   Пример позволяет показать карту, фильтры, карточку узла, таблицу и структуру coverage.
2. В форме выбрать регион backend либо задать четыре координаты. Область можно
   указать двумя кликами на карте или перенести границы видимого фрагмента.
   Названия произвольных регионов в координаты интерфейс не преобразует.
3. «Построить граф» отправляет реальный POST /api/graphs. Ответ 200 сразу открывает
   граф; ответ 202 запускает опрос задания. Проценты выполнения не выдумываются.
   Первая региональная выгрузка может быть большой и выполняется только по явному запуску.
4. «Прекратить ожидание» прекращает опрос браузером, но не отменяет задание в БД.
   Ожидание можно продолжить. job_id/graph_id сохраняются в URL и восстанавливаются
   после обновления страницы. Есть отдельное открытие результата по ID.
5. Для серверного графа переключение транспорта обращается к ?mode=…, coverage
   можно запросить отдельно. Экспорт использует настоящий endpoint backend и
   скачивает полный граф независимо от текущего фильтра. Ошибки матриц 422 отображаются.
6. Вкладка API содержит действующие ручки, безопасные GET-пробы, cURL текущей формы
   и скачивание корневого openapi.yaml. Это файл из репозитория; ручка /openapi.yaml
   не предполагается существующей на backend.
7. Консоль показывает реальные запросы: URL, метод, HTTP-статус, длительность,
   тело запроса и ответ. Журнал ограничен 80 записями, большие JSON сокращаются.
   Поля с паролями/токенами скрываются, cookie и секретные заголовки не записываются.
   В dev-режиме React StrictMode может отменять первый запуск проверки подключения;
   такие записи отмечены «Стоп» и не считаются ошибками backend.

На мобильном экране параметры территории раскрываются отдельной кнопкой.
Подложка карты требует доступности OpenStreetMap; при недоступности тайлов
сохраняется интерактивный граф и показывается соответствующее сообщение.

## Проверки

```sh
cd frontend
npm run lint
npm run build
npx playwright install chromium
npm run test:e2e
```

Основные браузерные тесты изолируют HTTP через Playwright: построение и polling,
кэшированный результат, обновление страницы, фильтр, coverage, экспорт, валидация,
ошибки, остановка/возобновление ожидания и мобильный экран. Реальный backend smoke
включается отдельно и допускает только регион `ui-fixture` из синтетического набора:

```sh
RUN_BACKEND_SMOKE=1 BACKEND_URL=http://127.0.0.1:18080 npm run test:e2e
```

Для него Go-сервис должен быть заранее запущен с отдельной PostgreSQL и каталогом
источников, указывающим на `backend/tests/testdata/freight.osm` и `references.json`.
Скриншоты создаются в игнорируемой директории `frontend/test-results`.
