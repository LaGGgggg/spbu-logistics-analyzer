# Архитектура backend

Имена прикладных сервисов отражают назначение и заканчиваются на `_service`.
Реализация хранения логистических данных называется `logistics_repository`;
PostgreSQL — технология её реализации.

Рабочий код, конфигурация, миграции и Makefile находятся в `backend/main`,
тесты — в `backend/tests`. Файлы `backend/go.mod` и `backend/go.sum` задают
общий модуль для обеих директорий. Запуск: `cd backend/main && go run .`;
проверки из той же директории: `make check`. Пути к конфигам по умолчанию
и локальным данным рассчитаны на запуск из `backend/main`.

## Слои и зависимости

| Директория | Ответственность |
|---|---|
| `backend/main/main.go` | Сборка зависимостей, запуск HTTP и воркеров, завершение процесса |
| `backend/main/domain/logistics` | Граф, узлы, дуги, координаты, границы и грузовая политика |
| `backend/main/domain/buildjob` | Состояния и сущность задания |
| `backend/main/service/logistics_service` | Запуск и чтение результатов, выбор области, выполнение фоновых заданий |
| `backend/main/service/graph_build_service` | Построение графа, объединение узлов, маршрутизация и пространственный индекс |
| `backend/main/repository/logistics_repository` | Хранение регионов, графов и заданий в PostgreSQL |
| `backend/main/repository/osm` | Чтение OSM, подбор источника, Overpass и кэширование выгрузок |
| `backend/main/repository/config` | Чтение и проверка конфигурации запуска |
| `backend/main/interfaces/httpapi` | Gin, HTTP-контракт, проверка запросов и преобразование ошибок |
| `backend/main/interfaces/export` | CSV, матрицы, GeoJSON и GraphML |
| `backend/tests` | Тесты по слоям; имена тестовых директорий соответствуют рабочим пакетам |

HTTP зависит от входного прикладного интерфейса `logistics_service.Queries`.
Прикладной слой зависит от домена и объявляет исходящие порты `Repository`,
`AreaResolver` и `Source`. Внешние адаптеры реализуют эти порты; домен не зависит
от Gin, pgx и OSM-парсера. Конкретные компоненты связываются в `main.go`.

## Разделение файлов

В `logistics_service` сценарии чтения и запуска находятся в `logistics_service.go`,
работа с произвольной областью — в `area_build.go`, выполнение заданий — в
`build_worker_service.go`. Контракты отделены в `ports.go` и `repository.go`,
результаты и состояния — в `build_result.go`, ошибки — в `errors.go`.

В `graph_build_service` построение находится в `graph_build_service.go`,
объединение узлов — в `nodes.go`, маршрутизация — в `routing.go`,
пространственный индекс — в `spatial.go`, контракты — в `ports.go`.

| Файл в `logistics_repository` | Ответственность |
|---|---|
| `connection.go` | Создание, проверка и закрытие пула подключений, конструктор репозитория |
| `initialization.go` | Миграции, пресеты регионов, блокировка экземпляра, восстановление заданий |
| `regions.go` | Чтение регионов и сохранение произвольной области |
| `build_requests.go` | Дедупликация запросов и постановка задания |
| `graphs.go` | Чтение графов |
| `jobs.go` | Чтение, захват, ошибка и возврат задания в очередь |
| `build_completion.go` | Сохранение графа и завершение задания одной транзакцией |
| `errors.go` | Преобразование ошибок pgx в прикладные ошибки |

Пул подключений закрывается владельцем: после `Open` сервер вызывает `Close`;
при передаче существующего пула через `New` его жизненным циклом управляет вызывающий код.
Разделение файлов сохраняет атомарность завершения задания, дедупликацию запросов
и существующее поведение HTTP API.

## Выборка OSM для области

При использовании региональной XML/PBF-выгрузки адаптер сначала индексирует
идентификаторы точек внутри запрошенных границ с буфером `maximum_snap_km`.
Затем отбирает линии, содержащие хотя бы одну такую точку, и связанные с ними
составные объекты. Геометрия выбранных линий и внешние участники выбранных
отношений загружаются целиком, включая точки за границей области. Лимит
`maximum_objects` применяется к пространственной выборке и её зависимостям,
а не ко всей транспортной сети исходного федерального округа. Он также
ограничивает размер промежуточного индекса и сохраняет защиту от больших областей.

Файл выгрузки по-прежнему читается последовательно в несколько проходов;
маленькая область сокращает потребление памяти, но не устраняет время чтения PBF.
В проходах PBF пропускается декодирование ненужных типов объектов.
Сеть ограничена выбранными линиями: маршрут с объездом за её пределами может
отсутствовать. Линия, пересекающая область без единой точки внутри буфера,
также не попадёт в выборку. Это ограничение отражено в `coverage.warnings`.

Версия алгоритма участвует в идентификаторе произвольной области. После изменения
алгоритма новый запрос тех же границ создаёт новую область; существующие задания
и графы остаются в истории.
